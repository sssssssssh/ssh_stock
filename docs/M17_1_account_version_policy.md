# M17.1 冻结账户版本策略

状态：设计与现行行为说明已交付。旧版本独立运行、账户继承和资金迁移均为 **DEFERRED，未实现**。

## 现行约束

`paper/account_state.py::account_settings()` 先复核账户 record_json/hash 与配置摘要，
再把冻结 source_contract 与当前服务比较。现有字段包括 algo_version、strategy_hash、
opportunity_hash、factor/state/status/opportunity 版本。不同则返回 PAPER_SOURCE_VERSION_DRIFT，
不能仅因为新版本“看起来兼容”而接着记账。账户、策略或配置快照不原地改写。

| 情景 | 当前允许的操作 | 禁止的操作 |
|---|---|---|
| 冻结合同与当前服务一致 | 当前版本来源完整且连续时正常 PAPER EOD | 隐式更新冻结配置或跳过缺口 |
| 不一致，但旧服务与资料仍可验证 | 研究独立旧版本运行；默认关闭，需独立验收 | 新信号接旧账、共用写入口或跳过版本检查 |
| 旧版本无法安全运行 | 暂停推进，保留只读历史、已有导出/分页能力；人工决定关闭旧账户、新建独立账户 | 重标旧 NAV、改旧 Hash、静默换版本 |

账户状态没有 MIGRATION_REQUIRED 这个新枚举。本阶段不增状态或迁移字段；错误码及
审计表示“需要人工处理”，不可声称已经实施自动迁移。只读汇总仍按冻结金融记录读取，
不调用最新模型来重算旧收益。已有明细 API 可分页获取，未新增整账户一键导出功能。

## 升级检查

1. 先备份、暂停旧账户和自动推进，记录原提交、镜像、0053、配置与来源摘要。
2. 列明算法/配置身份变化，复核独立 PG17、财务不变量及同 HEAD CI。不得降低旧账户的版本门禁。
3. 当前 source_contract 未列出全部 market/sector/theme 版本，不能据此推断这些算法升级兼容。
   这些变化必须在后续任务中显式设计完整身份版本，或停止旧账户并新建；本阶段不改旧合同形状。
4. 若需要继续旧版本，应使用已固定镜像、原配置与可验证来源的隔离服务和权限边界。
   当前代码没有版本路由/多代调度功能，不得直接同时启动两代 Worker 写同一账户。
5. 回滚先关闭功能，保留所有历史；已有 PAPER 数据时不得强制降级或清账。

## 后续账户继承设计

若另行批准实施，应创建新账户和 append-only 继承凭证，至少记录 parent_account_id、
继承日期/切分点、原账户与配置身份、资金/逐股数量/成本/可卖状态、来源冻结 Hash、审批人及原因。
切分前后分别复核会计守恒与 T+1；没有原始证明不得继承，不能只复制一个总资产数字。
首版不迁移在途委托，不从历史记录生成伪成交。新旧 NAV 与策略绩效分别统计，跨策略不拼接。
上述字段仅为后续设计，不是当前数据库已有列，也不构成自动资金迁移授权。
