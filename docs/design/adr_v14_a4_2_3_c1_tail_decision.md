# ADR A4-2.3：不把 GC 相关性当作 C1 尾部修复证明

状态：P0 审阅交付，PERFORMANCE_OPEN；P1/P2/P3 NOT_AUTHORIZED。

## 事实与反证

原始数据及每个 C0/C1 控制样本见[基线](../acceptance/v14_a4_2_3_baseline.md)。
历史 1100 个样本完整、原旋转顺序完整、Golden 一致；全部 summary/whole/decision 确定性重算一致。
原统计快表 C0/C1 P95=0.13734849275002717/0.07412675995006453s；
analyzed=0.08875597779998542/0.19159500049996722s，比值约2.159，失败必须保留。

analyzed C1 有七个样本超过 C0 P95×1.10：repeat5/13/19/25/41/66/81（0起）。
其中前六个 GC 约0.127–0.144s；repeat81 GC仅约0.001449s，execute约0.060648s。
GC 较大的样本不全落在 next(rows) 内：repeat66 row≈0.018332s、GC≈0.127124s，
说明回收可能落在其他 Python 映射/构造等阶段；不能说所有 GC 都发生于 buffered row materialization。
analyzed C0 也有四个约0.18–0.22s尖峰；原统计 C1 也有一个0.181768s尖峰但整体P95仍通过。
每个快表 C0/C1 样本 gc_count 都为16；计数不是分代或分配者证据。

两个慢表 B 缺失的范围负探测仍支持 CODE_SQL_PRIMARY；该结论与快速 C1 的 Python 尾部归因分开。
backend CPU区间约0.03–0.06s、不见采样 blocker，支持上述快速尖峰主要非数据库长查询的解释，
但 CPU采样含计时外观察器、轮询不能排除瞬时等待，不能推断数据库绝无贡献。

## 对测量实现的审查

- C0/C1 复用冻结 Python 方法；只在 Proxy.execute 中替换候选过滤片段，typed composite、A OFFSET0、B优先、删除与原像不变。
- JSON临时替换与 ws.db Proxy 在 finally 恢复；新的功能性回归同时验证成功/中途异常、一次 execute/mappings 迭代。
- Proxy每批建类，Rows.mappings 逐行 next 计时；额外动态类/闭包、Telemetry每样本创建engine/reader、已保存输出对象可产生对象分配。
  这些路径对 C0/C1 对称。静态可见分配不等于已证明它造成C1 P95差异。
- observe_gc 在进入 Telemetry 后注册、在 Telemetry退出采样前解除；finally 清理正常。
  真实wall从完整workload前开始、结束于workload返回，GC/JSON/行映射真实成本保留。
  观察器入退、原子写盘、快照和Golden比较在wall外；长C0查询中Telemetry后台线程可重叠。
- 原数据没有GC分代/分配栈、GC对象归属、同一快照observer反事实。五方案轮换但非独立进程，先慢后快、跨样本对象累积。
  暂无足够证据把 P95 差异归于某个生产行物化代码或 observer 的单一缺陷。

结论 **CORRELATED_NOT_CAUSAL**。不能把GC从wall扣除、关闭GC、改变重复次数或事后选C2作为已批准生产赢家。

## 选择与拒绝

选择：交付历史复算、完整样本分解、严格拒绝收据与失败关闭测试；不启动没有合理候选的新性能实验。
拒绝：未证明因果即预计算列名/替换生成器/移除行计时，或提高P95阈值；这些既不能保证修复，也越过精确C1生产差异边界。
拒绝：通过修改observer取得更好分位数再与旧口径宣称收益。任何新测量协议必须用户先审阅，且C0/候选同口径重测。
拒绝：反复提交触发同一100次试验。因此本轮 lookup Job 保留小型PG17安全回归，但改为离线复核历史工件，不运行新性能矩阵。
这不是跳过已授权验收：本轮前置条件失败，正式性能/生产/容量阶段明确未授权，Release Gate仍失败。
