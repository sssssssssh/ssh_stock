# 部署与备份

## 资产范围

必须备份：

- 外部 PostgreSQL 数据库
- 服务器 `.env`
- `config/*.yaml`

不要把 `.env`、数据库 dump、真实 Token 或密码提交到 Git。代码和迁移文件由 Git 保存，数据库结构由 Alembic 管理。

## Compose 部署

宿主机只需 Docker Engine、Docker Compose 和可访问的外部 PostgreSQL 17。复制 `.env.example` 为 `.env`，填写 `DOCKER_DATABASE_URL`、Tushare 配置和管理员配置后执行：

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=200 backend worker scheduler frontend
```

默认页面为 `http://127.0.0.1:5173`。需要公网监听时设置 `FRONTEND_BIND=0.0.0.0`，并使用 HTTPS 反向代理、云防火墙和 `AUTH_COOKIE_SECURE=true`。数据库不在 Compose 内，迁移容器成功执行 `alembic upgrade head` 后业务服务才启动。

## PostgreSQL 备份

优先在 PostgreSQL 17 客户端执行 custom format 备份。连接参数应通过交互密码、`.pgpass` 或受保护的环境变量提供，不要把密码写进脚本：

```bash
pg_dump --format=custom --no-owner --no-privileges \
  --dbname="postgresql://USER@HOST:5432/DBNAME?sslmode=require" \
  --file="ssh_stock_$(date +%Y%m%d_%H%M%S).dump"
```

Windows PowerShell 可使用：

```powershell
$stamp = Get-Date -Format "yyyyMMdd_HHmmss"
pg_dump --format=custom --no-owner --no-privileges `
  --dbname="postgresql://USER@HOST:5432/DBNAME?sslmode=require" `
  --file="ssh_stock_$stamp.dump"
```

`pg_dump` 使用一致性快照，不要求长时间停库。为避免业务状态变化造成验收歧义，正式迁移前应暂停 scheduler/worker，不再提交新任务，等待 RUNNING 任务结束后再备份。定期做恢复演练，并把 dump 存到与数据库服务器不同的位置。

## 恢复流程

1. 停止旧环境的 scheduler、worker 和 backend，避免恢复期间写入。
2. 新建空 PostgreSQL 17 数据库和最小权限业务账号。
3. 恢复 custom format dump。
4. 更新 `.env` 的 `DATABASE_URL/DOCKER_DATABASE_URL`，恢复 `config/*.yaml`。
5. 执行 `python -m alembic upgrade head`，或启动 Compose 让 migration 服务升级结构。
6. 启动服务，检查 `/health`、登录、`/api/v1/system/runtime` 和数据页日期。

恢复命令示例：

```bash
pg_restore --clean --if-exists --no-owner --no-privileges \
  --dbname="postgresql://USER@HOST:5432/NEW_DB?sslmode=require" \
  ssh_stock_20260924_120000.dump
```

对非空目标库执行 `--clean` 会删除 dump 中已有对象，只能用于明确指定的恢复数据库。生产恢复前必须再次核对目标主机和数据库名。若只验证备份，应恢复到独立测试数据库。

## 升级后的计算

Alembic 只处理结构，不拉取或重算数据。Analysis Identity 发生变化时不要清空 Raw；先对目标历史区间运行 Recalculate，再运行 Research Eval。恢复后若配置文件与备份时不同，应先确认当前 Hash 和数据覆盖范围，再决定补算区间。
## Milestone 12 生产鉴权要求

生产环境必须配置 `APP_ENV=prod`、至少 12 位且不为默认值的 `BOOTSTRAP_ADMIN_PASSWORD`，并设置 `AUTH_COOKIE_SECURE=true`。示例文件只保留开发占位值，不应复制为生产密码。`AUTH_LAST_SEEN_UPDATE_MINUTES` 默认为 10；登录失败窗口、次数和锁定秒数分别由 `AUTH_LOGIN_FAILURE_WINDOW_SECONDS`、`AUTH_LOGIN_MAX_FAILURES`、`AUTH_LOGIN_LOCKOUT_SECONDS` 控制。
