# 计算批次可观测性验收

基线：`28723c7`。开发验收时为工作区补丁；后续按用户要求提交推送，不部署、不重启云端或本机业务 Worker。

## 交付范围

- 增加输入读取/整理、计算、范围核对、候选查询/正式结果核对/准备/暂存、逐表发布的固定标签日志。
- 每 500 行候选批次记录批次号/总批次、已处理/总行数和耗时；既有独立任务心跳记录当前操作等待。
- Job 元数据保存最新操作及最近 12 条事件，页面单独显示步骤进度、耗时和记录；未知分母显示 `--`。
- 心跳进度写入校验状态/执行者/token，合并 JSONB，不回盖较新快照，不回退推进时间；有限等待失败不影响业务事务。
- 重复心跳和等待计时不伪造真实业务推进；候选暂存明确不是已提交、已发布或可续跑检查点。
- 不修改 Raw/计算公式/版本/预热/候选批大小/原子发布/发布预算，不引入迁移，不宣称修复候选查询性能。
- 不为加载此补丁打断用户正在运行的任务；下一次安全重启 Worker 后生效，旧任务不回填。

前端依赖、覆盖率和构建在忽略目录的独立副本中执行，不替换正在运行的开发服务依赖。
浏览器测试拦截全部业务 API，使用合成响应，不创建真实任务。

原版复现记录见 [读取超时修复验收](20261019_recalculation_read_timeout.md)。

## 使用边界

页面明细持久化沿用任务心跳周期（默认 45 秒），页面轮询仍为 5 秒；操作计时本地每秒更新，
不能视为真实 SQL 进度。最终发布事务锁住任务行时，旁路明细可以有限等待失败，以日志及最终发布状态为准。
本补丁没有让当前旧 Worker 热加载，不改变其执行身份，也不自动取消、重提或续跑用户任务。
开发验收时只读核对该旧任务仍为 RUNNING、未请求取消且没有新批次快照，符合不打断在途任务的边界。
专用测试 PostgreSQL 已关闭；原本地前端、后端和业务 Worker 保持运行，Scheduler 未开启。
没有 Schema、依赖或部署修改，不执行业务库迁移、Docker 构建或自动部署；未执行同 SHA CI。

## 后续取消操作

用户在开发验收后明确要求提交推送并取消当前旧补算任务。正常取消接口在任务行的
`FOR UPDATE` 锁等待中超时，事务回滚；未据此伪造取消成功。
随后保持既有数据通道 advisory lock 顺序，使用 `FOR NO KEY UPDATE` 核对唯一目标，
校验 RUNNING、任务类型、父链、worker、执行 token 和执行确认状态，再以执行身份 CAS
仅写入 `cancel_requested` 及首次请求时间。未修改状态、token、候选或已发布数据。
独立连接确认取消请求已提交；核对时仍为 RUNNING，等待旧 Worker 到达安全取消检查点。
未强杀进程、终止 SQL、释放执行槽位、自动重提任务或启动 Scheduler。
