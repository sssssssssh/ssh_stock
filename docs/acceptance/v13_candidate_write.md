# V1.3 有界候选暂存

W03 复用同批精确查询返回的当前行、public 原像与事务时间，不再重复查询 A/now。
来源登记与质量凭据失效合并为原表的单次 ON CONFLICT，已缓存凭据同时失效，不能借旧质量放行。
每 500 条候选仍使用正常 INSERT/ON CONFLICT、原约束与触发器；单个 JSON 参数经原生 composite
还原类型，冲突仍只更新原白名单，首次 base_row 不更新。Raw upsert、事务及发布预算不变。

## 查询计划修正

初步 plain join 会选择全局 Hash Join；单独 LATERAL/equality 在空统计下仍会选择 date 前缀索引，
每个键过滤大量旧候选。两次探索实验保留为未完成收据，不当作通过的性能结果。
最终对非 NULL、全序的完整主键使用相同起止闭区间（等价点查）及完整键排序/唯一上限，
实测走 pk_data_publication_row，500 loops、每次最多 1 行、无过滤无关候选。
public 仍是同一事务的自然键参数化查询，删除掩码继续遮蔽 A。
空统计、事务内增长的真实 PG EXPLAIN 纳入强断言，不能将该形式随意简化后仅依赖暖统计。

## 阶段回归

41 项发布/黄金/独立心跳回归通过；最终主键访问版本的 9 项黄金/心跳及 2 项计划/缓存质量回归通过。
公开 A 与已发布身份未因候选检查或诊断而提前提交；未增加迁移、临时表或生产操作。
10 万行当前首轮摘要与旧实现相同，候选 SQL 从 840 降为 420；该数字尚未包含 W05 新增的取消检查成本。
运行耗时与 WAL 有本机其他合成负载干扰，不能据此宣布 50% 总耗时目标或生产容量通过。
最终性能、取消保护和 CI 结果在专项收尾矩阵统一报告。
